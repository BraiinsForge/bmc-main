# 26.10 technical release notes

Implementation notes behind the [26.10 changelog](../../CHANGELOG.md), by component. Bullets that apply to one device
are tagged `[Deck]` or `[BMM101]`; the rest apply to both.

## Widgets built against the 26.09 SDK

The widget SDK moves from 0.6.0 to 0.9.0; the device launcher stays `bmc-wasm-thin-v0`. The host keeps every function a
0.6 build imports and checks the major version only, so a widget built against the 26.09 SDK loads and runs on the 26.10
core. The official widgets ship with the core, so this concerns third-party widgets that are not rebuilt. Backward
compatibility has these limits:

- `TextOverflow::Ellipsis` and `TextOverflow::Clip` now cut a line at the box edge and let the box shrink inside a row.
  In 26.09 they only stopped wrapping, so text that fit before may now end in `…`; the 26.09 Formula 1 build, for
  example, renders its lap times as `1:11.…` on the 26.10 core. A widget that used either mode only to keep text on one
  line should pass the text through `bmc_wasm_sdk::typography::unbroken` instead.
- SVG group opacity is applied to path paint, so a tinted icon keeps its own transparency.
- Manifest defaults are checked against their own rules at discovery: a timezone default outside its list or a number
  option outside its `min`/`max` refuses the widget. A required top-level string parameter may keep an empty default, as
  26.09 manifests do; an empty default in a list item or object field is refused, and an empty submitted value stays
  invalid.

## Protocol changes

The gRPC web API, the Wayland protocols and the wasm host ABI are interfaces between components shipped together, not
public interfaces, so a breaking change between releases is permitted where it is needed. The Wayland protocols are
extended compatibly where they can be, by interface version and `since` attributes, and replaced by a new interface name
only when the change cannot be expressed that way. The wasm host ABI, which third-party widget builds import, is kept
backward compatible.

### gRPC web API (`bmc-grpc/proto/web/`)

- Removed: `hardware.proto` with `HardwareService` and `HardwareCapabilities`, which a 26.09 web UI tab left open across
  the upgrade still calls; `widget_data.proto` with `WidgetDataValue` and `WidgetDataStruct`.
- `field_schema.proto`: `FieldValue`, `FieldValueList` and `FieldValues` replace the widget-data messages and add list
  and object kinds; `ParamArray`, `ArrayItemKind`, `UniqueKeys` and `ParamObject` describe list and object parameters;
  `EnumControl`, `placeholder`, `unit`, `min_length` and `max_length` are added to the scalar parameters.
- `scene_management.proto`: scene and widget `params` change type from `WidgetDataStruct` to `FieldValues`; the scalar
  field numbers are unchanged.
- `initial_setup.proto`: `PoolConfig`, `hostname` and `NetworkConfig` fields on the setup messages, and a `SkipWifi`
  call.
- `metadata.proto`: `packages_version` beside the firmware version.

### Wayland protocols

- `deck_widget_manager_v2` and `deck_widget_surface_v1` are replaced by `deck_widget_manager_v3` and
  `deck_widget_surface_v2`: params, credentials and credential secrets arrive as a sealed memfd plus byte length instead
  of a JSON string argument. Only the wasm host speaks this protocol, so wasm widgets are unaffected.
- `deck_platform_v1` is new (version 3): a `capabilities` bitfield (`wifi`, `ethernet`, `mining`, `boser_managed`), a
  `product_name` event and a `display_info` event with width, height and shape.
- `deck_device_info_v1` version 2: `report_ip` event and a `switching_uplink` state.
- `deck_upgrade_v1` version 3: `cleared` event and a `rebooting` state.

## Devices and platform integration

- `bmc-platform`: the display application runs on BMM101 with its own profile: default scene set, screen-specific widget
  layouts, settings tray, brightness handling, IP-report button, mining-status indicator and upgrade overlay `[BMM101]`.
- `bmc-platform`: hardware capabilities (WiFi, ethernet, mining, alarm output, sound, LED) gate the backend services and
  the system overlays. `AlarmService` is registered only with alarm output; on Boser-managed platforms the system,
  timezone, automatic-upgrade and network mutations answer `UNIMPLEMENTED`, and upgrade check and start are translated
  to Boser's REST API, answering `UNAVAILABLE` when Boser cannot be reached `[BMM101]`.
- `frontend`: reads the same capabilities and Boser branding from `/system.js` and hides the controls a device lacks.
- `bmc`: the root web address redirects to the miner controls; display settings are reachable from there `[BMM101]`.
- `bmc`: timezone changes arrive through Boser's stream on managed devices `[BMM101]`.
- `bmc-field-schema`: new local-file token account type. The mining widgets and status indicator read the miner through
  a read-only BOS API token delivered by credential resolution, so a web-password change does not break them `[BMM101]`.
- `bmc-net`: networking rewritten into in-repo crates with the `nl80211` `[Deck]` and `esp32` `[BMM101]` WiFi drivers; a
  failed join names its reason and restores the saved key.

## Packages and upgrades

- `bmc-nix`: release-channel fallback and nightly feed variants; feed checks are bounded to the current package closure;
  firmware entries sharing a Nix pin reuse one init tarball.
- `bmc-nix`: signed init tarballs resume after an interrupted download, and corrupted partial downloads are recovered.
- `bmc-nix`: install-if-missing profile change. The core package carries a widget auto-install step that runs it on
  activation, so an upgraded device gets a widget new to the release, Fleet Management in 26.10, without a visit to the
  Display Widgets page.
- `bmc`: the installed packages version is stamped into the core package and exposed over `MetadataService`; the web UI
  shows it apart from the firmware version.
- `bmc-upgrade`: offers are fingerprinted, so a repeated check keeps a pending offer valid across browser tabs.
- `bmc-upgrade`: Boser-managed backend beside the BMC-managed one; Boser upgrade state is projected into the upgrade
  display and package upgrade requests are routed through Boser `[BMM101]`.
- `bmc-upgrade`: package apply failures keep their type through the upgrade protocol.
- `bmc`: widgets are paused before a firmware download to free memory and restored if the upgrade fails.
- `bmc`: boot no longer lights the display at full brightness before the configured level applies.

Reference: [`docs/devel/upgrades.md`](../devel/upgrades.md),
[`docs/devel/firmware-package-interlinking.md`](../devel/firmware-package-interlinking.md).

## Widget runtime and rendering

- `bmc-render`: static layers are reused and animated frames report damage per draw, so a frame repaints only the
  regions that changed.
- `bmc-render`: compositor-side tray blitting and buffer handling fixes remove redundant GPU work and flicker; fixes
  around static-layer lifetime, damage after a failed frame, animation transforms and modal overlays.
- `bmc-render`, `bmc-wasm-runtime`: one shared animation cadence. Animated Deck scenes reach up to 30 frames per second;
  ISS Position's globe and the analog clock hand animate `[Deck]`.
- `bmc-render`: `TextOverflow::Clip` and `TextOverflow::Ellipsis` cut text that does not fit.
- `bmc-wasm-runtime`: widget timers wake the host main loop when due and a widget may change a timer's period.
- `bmc-wasm-sdk`: `Socket`, `Ws`, `HttpListener` and the discovery handles are move-only.
- `bmc-wasm-sdk`: `Ratio`, `BitcoinAmount` and `Hashvalue` quantities; hashrate and power scale by SI prefix; bitcoin
  amounts render to the satoshi; time formats natively through the shared core.
- `bmc-wasm-sdk`: mDNS discovery and advertisement on both targets.

Reference: [`docs/devel/wasm-widgets/`](../devel/wasm-widgets/),
[`docs/devel/widget-lifecycle.md`](../devel/widget-lifecycle.md), [`docs/architecture/`](../architecture/).

## Widget installation and configuration

- `bmc-upgrade`: the Display Widgets page installs a plain WebAssembly widget from a `.nar` archive, refusing one whose
  folder or uid clashes with an installed widget. System packages are outside this path `[Deck]`.
- `bmc-field-schema`: manifests declare list parameters beside scalar ones. The form adds, removes and reorders entries,
  reports invalid values in place and shows descriptions for toggles. Defaults and entered values go through one
  validator.
- `bmc`: widget credentials bind to saved accounts instead of living in widget settings; a userpass account derives HTTP
  Basic, a local-file account delivers a token file.

Reference: [`docs/uploading-wasm-widgets.md`](../uploading-wasm-widgets.md),
[`docs/devel/widget-manifest.md`](../devel/widget-manifest.md),
[`docs/devel/widget-runtime-configuration.md`](../devel/widget-runtime-configuration.md).

## Fleet Management

- Discovers BOS and AxeOS miners through mDNS; BOS is identified by its mDNS TXT record before authentication is chosen.
  BOS needs a saved account, AxeOS none.
- Hashrate history accumulates across polls for the fleet and each miner, and keeps updating while another scene is
  shown.
