# BDK-252 Stage 1: Prerequisites — Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make production ARM binaries self-contained (no `launch.sh`, no `LD_LIBRARY_PATH`), implement profile building in `bmc-nix`, and provide a dev deploy script that copies a binary + its Nix closure to the device.

**Architecture:** Three parallel workstreams: (1) Enable `wrapNixGL` on ARM glibc build profiles so `buildCrate` wraps widget binaries with Mesa environment variables, plus remove the redundant `wrapWithLibs`/`LD_LIBRARY_PATH` mechanism from `mkWidgetPackage`, (2) new `bmc-nix` crate with profile/hooks/CLI, (3) shell script that copies a binary + its Nix closure to the device. Note: `bmc-openwrt` is statically linked (musl) and already runs without `LD_LIBRARY_PATH`. The `wrapNixGL` work targets dynamically linked **widget** binaries (glibc profile). A custom Mesa overlay for self-contained DRI discovery is deferred to a later stage. All three converge at the success criteria: widgets run on device without `launch.sh` or manual environment variable overrides.

**Tech Stack:** Nix Flakes, Rust (tokio, clap, serde, thiserror, walkdir), ARMv7 cross-compilation (musl + glibc), Mesa/libglvnd

## Subtask 1: Nix workspace/build helpers — wrapNixGL for ARM glibc builds

**What needs to happen now:** apply the `wrapNixGL` and

### Task 1.1: Enable wrapNixGL on ARM glibc profiles and remove wrapWithLibs

**Rationale:** Instead of recompiling Mesa with a custom overlay (deferred
to a later stage), use the existing `wrapNixGL` mechanism from nix-lib.
When `wrapNixGL = true` on a build profile, `buildCrate` generates a
wrapper script that sets `LIBGL_DRIVERS_PATH`, `GBM_BACKENDS_PATH`,
`__EGL_VENDOR_LIBRARY_FILENAMES`, and `LD_LIBRARY_PATH` with the correct
Mesa/libglvnd store paths. This is the same mechanism nixGL uses.

The wrapper is generated at the `buildCrate` level (in nix-lib's
`wrapper.nix`), so the per-widget `wrapWithLibs` + `makeWrapper` +
`LD_LIBRARY_PATH` mechanism in `mkWidgetPackage` becomes redundant and
should be removed.

**Files:**
- Modify: `nix/workspace.nix` (ARM glibc build profiles — add `wrapNixGL = true`)
- Modify: `nix/mkWidgetPackage.nix` (remove `wrapWithLibs` mechanism)
- Modify: `nix/workspace.nix` (widget definitions — remove `wrapWithLibs: true`)
- Modify: `nix/mkAllWidgets.nix` (remove `wrapLibs` parameter)
- Modify: `nix/workspace.nix` (package outputs/callers — remove `wrapWithLibs` usage for widgets)

**Step 1: Add `wrapNixGL = true` to ARM glibc profiles**

In `nix/workspace.nix`, the ARM glibc profiles currently
don't set `wrapNixGL`, so it defaults to `false` (from
`mkBuildProfile.nix`). Enable it:

```nix
# nix/workspace.nix, ARM glibc profiles
armv7-glibc-release = workspace.mkBuildProfile {
  suffix = "armv7";
  minimal_deps = true;
  rustProfile = "release";
  rustCrossTarget = "armv7-unknown-linux-gnueabihf";
  build_pkgs = fixedArmv7Pkgs;
  wrapNixGL = true;
};
armv7-glibc-debug = workspace.mkBuildProfile {
  suffix = "armv7";
  minimal_deps = false;
  rustProfile = "dev";
  rustCrossTarget = "armv7-unknown-linux-gnueabihf";
  build_pkgs = fixedArmv7Pkgs;
  wrapNixGL = true;
};
```

When `wrapNixGL = true`, `buildCrate.nix` extracts `mesa` and `libglvnd`
from `profile.build_pkgs` (which is `fixedArmv7Pkgs`) and generates a
wrapper script via `wrapper.nix` that sets the GL environment variables.

**Step 2: Simplify mkWidgetPackage — remove wrapWithLibs**

In `nix/mkWidgetPackage.nix`, `mkWidgetPackage` currently accepts
`wrapWithLibs` and conditionally uses `makeWrapper` to set
`LD_LIBRARY_PATH`. Since the `wrapNixGL` wrapper from `buildCrate` now
handles Mesa/GL and `LD_LIBRARY_PATH`, this is redundant.

Remove:
- The `wrapWithLibs` parameter
- The `runtimeLibs` list
- The `nativeBuildInputs` with `makeWrapper`
- The conditional `makeWrapper` / `LD_LIBRARY_PATH` logic

The simplified `mkWidgetPackage` just copies the binary:

```nix
{ pkgs, lib, widgetsRoot ? ../widgets }:
{ name, crate, profile, features ? [ ] }:
let
  binary = profile.buildCrate crate { inherit features; };
  widgetSrc = widgetsRoot + "/${name}";
in
pkgs.runCommand "bmc-widget-${name}" { } ''
  mkdir -p $out/lib/bmc-widgets/${name}/bin
  cp ${widgetSrc}/manifest.json $out/lib/bmc-widgets/${name}/
  cp ${binary}/bin/* $out/lib/bmc-widgets/${name}/bin/
  if [ -d "${widgetSrc}/assets" ]; then
    cp -r ${widgetSrc}/assets $out/lib/bmc-widgets/${name}/
  fi
''
```

Functions to implement in `profile.rs` (see `bmc-nix.md:467-531`):

- `build_symlink_tree(tmp_path, packages)` — walk each package's store

- `build_profile(profile_dir, generation, packages, hooks_dir_name)` —

```
│   ├── lib/
│   ├── hooks/
│   ├── activation/
```

```rust
use crate::types::*;

/// Resolve all packages in an index to ResolvedPackages.
///
/// Used by bmc-nix-cli build-profile when packages are already in the
/// local Nix store. Uses Stage 1 defaults (installed_by=System,
/// installed_from="local", pinned=false).
pub fn resolve_all_from_index(
    index: &PackageIndex,
) -> anyhow::Result<Vec<ResolvedPackage>> {
    index.packages.iter().map(|entry| {
        let cache_url = resolve_cache_url(entry, &index.caches)?;
        Ok(ResolvedPackage {
            name: entry.name.clone(),
            version: entry.version.clone(),
            store_path: entry.store_path.clone(),
            cache_url,
            min_bos_version: entry.min_bos_version.clone(),
            min_bmc_version: entry.min_bmc_version.clone(),
            category: entry.category.clone(),
            description: entry.description.clone(),
            upgrade_strategy: entry.upgrade_strategy.clone(),
            install_strategy: entry.install_strategy.clone(),
            installed_by: InstalledBy::System,
            installed_from: "local".into(),
            pinned: serde_json::Value::Bool(false),
        })
    }).collect()
}

fn resolve_cache_url(
    entry: &PackageEntry,
    caches: &[CacheEntry],
) -> anyhow::Result<String> {
    match &entry.cache {
        Some(name) => caches.iter()
            .find(|c| c.name == *name)
            .map(|c| c.cache_url.clone())
            .ok_or_else(|| anyhow::anyhow!(
                "cache '{}' not found for package '{}'", name, entry.name
            )),
        None => caches.first()
            .map(|c| c.cache_url.clone())
            .ok_or_else(|| anyhow::anyhow!(
                "no caches defined for package '{}'", entry.name
            )),
    }
}
```

## Subtask 3: Dev Deploy Script

### Task 3.1: Write deploy script

**Files:**
- Create: `scripts/deploy-nix.sh`
- Modify: `docs/devlogs/deployment.md` (add section)

**Step 1: Design decision**

The key challenge: `cargo build` output is NOT in the Nix store, so we
can't compute its closure. Use `nix build` instead — it's simpler and
correct. Developers who need faster iteration can use the mock binary
(x86_64) or `scp` just the binary (the closure only needs copying once
or when deps change).

**Chicken-and-egg problem:** `nix copy --to ssh://root@$DEVICE_IP`
requires a working `nix` binary and store database on the target device.
In Stage 1, the device does not have Nix installed yet (that comes in
Stage 2 with the tarball). Therefore the script uses a **file-based
approach**: build locally, compute the closure, then `rsync` the store
paths as plain files to the device.

**Step 2: Write the script**

```bash
#!/usr/bin/env bash
# Deploy a Nix-built package to the Deck.
# Copies the package + its full Nix closure to the device's /nix/store.
#
# Usage: ./scripts/deploy-nix.sh <package> [device-ip]
#
# Examples:
#   ./scripts/deploy-nix.sh bmc-openwrt-armv7-release 192.168.1.2
#   DEVICE_IP=192.168.1.2 ./scripts/deploy-nix.sh widgets-armv7-release
#
# Prerequisites on device:
#   - /nix bind mount exists (e.g. /mnt/data/nix -> /nix)
#   - SSH access as root
#   - No Nix binary or DB required (plain file copy)
set -euo pipefail

pkg="${1:?Usage: deploy-nix.sh <package> [device-ip]}"
device="${2:-${DEVICE_IP:?Set DEVICE_IP or pass as second argument}}"

echo "Building .#${pkg}..."
store_path=$(nix build ".#${pkg}" --no-link --print-out-paths)

echo "Computing runtime closure..."
closure=$(nix path-info --recursive "$store_path")

echo "Syncing $(echo "$closure" | wc -l) store paths to ${device}..."
# Use rsync for efficient incremental transfer.
# Only copies paths that are missing or changed on the device.
printf '%s\n' $closure \
  | rsync -av --files-from=- / "root@${device}:/"

echo "Done. Package at: ${store_path}"
echo "Run on device: ${store_path}/bin/<binary-name>"
```

Key behaviors:
- Uses `nix build --no-link --print-out-paths` to get the store path
- Uses `nix path-info --recursive` to compute the full runtime closure
  (all transitive dependencies)
- Uses `rsync` to copy store paths — no `nix` binary needed on device,
  efficient incremental transfers (only missing/changed files copied)
- The device just needs `/nix/store/` to be a writable directory

**Limitation:** Without a Nix DB on the device, `nix` commands won't
work on the device itself. This is fine for Stage 1 (dev testing). In
Stage 2, the tarball provides a proper DB via `nix-store --load-db`.
