# BDK-252 Stage 7: Self-Initialization — Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** The device can bootstrap its own Nix store on first boot or
after factory reset, without manual tarball extraction. A new
statically-linked binary (`bmc-nix-init`) runs before the Nix store
exists, handles WiFi setup if needed, downloads and extracts the
initial tarball, and activates the first profile. A companion
`bmc-nix-init-mock` crate allows testing on a regular computer.

**Prerequisites:** Stages 1-6 complete — `bmc-nix` crate fully
implemented (including `store::init_store()`), deployment indexes
(factory index with tarball URLs), init tarball building, autopatchelf.

**What already exists (from Stages 1-4):**
- `bmc-nix/src/profile.rs` — `activate_profile()`, `lock_profile()`,
  `next_generation_number()` (sync, not async!), `build_profile()`
- `bmc-nix/src/manifest.rs` — `build_manifest()`, `write_manifest()`
  (both sync)
- `bmc-nix/src/types.rs` — `PackageIndex`, `PackageEntry`,
  `ResolvedPackage`, `Manifest`, `ManifestPackage`,
  `ProfileGeneration`
- `bmc-display/` — Slint UI framework with `.slint` files
- `nix/init-artifacts.nix` — tarball and index building
- `nix/packages.nix` — package definitions

**What will exist after Stages 5-6 (prerequisites):**
- `bmc-nix/src/store.rs` — `init_store()`, `copy_store_paths()`,
  `DownloadProgress` trait
- `bmc-nix/src/manifest.rs` — `read_manifest()`
- `bmc-nix/src/types.rs` — `FactoryIndex`, `FactoryTarball`,
  `ServersConfig`, `FactoryServerEntry`, `GcConfig`

**Exact Stage 5 APIs this stage depends on:**
- `store::init_store(client, factory_server, bos_version, progress)`
  → `Result<InitStoreResult, InitStoreError>`
- `store::DownloadProgress` trait with `on_bytes_downloaded()`,
  `on_phase()`
- `store::InitStoreError` error type
- `manifest::read_manifest(profile_path)` → `Result<Manifest,
  ReadManifestError>`
- `types::ServersConfig` with `.factory` field
- `types::FactoryServerEntry`

**Reference patterns (not dependencies):**
- `bmc/src/initial_setup.rs` — WiFi setup flow (AP mode pattern)
- `bmc-openwrt/` — real hardware binary pattern
- `bmc-mock/` — mock binary pattern

**Architecture decision:** Follow the three-crate structure of `bmc` /
`bmc-mock` / `bmc-openwrt`, but with a **narrower trait abstraction**
(`WifiManager` only) instead of a mega-trait like `BmcManager`. The
init binary's scope is limited to store bootstrapping.

- `bmc-nix-init/` — library crate with shared init logic, state
  machine, `InitStateObserver` trait, and Slint display code.
  Both binaries share the same Slint UI.
- `bmc-nix-init-openwrt/` — real hardware binary (statically linked,
  musl). Uses DRM backend and real WiFi manager.
- `bmc-nix-init-mock/` — mock binary for desktop testing. Uses
  Slint's windowed backend for previewing the UI.

**Note on naming:** The concept docs (`nix-daemon-details.md:22`)
use `bmc-nix-initializer`. This plan uses `bmc-nix-init` for brevity.
The binary name produced by Cargo will be `bmc-nix-init-openwrt` —
use `[[bin]] name = "bmc-nix-init"` in the openwrt crate's
`Cargo.toml` to produce the expected binary name, or add a rename
step in the Nix build.

**Display placement:** Slint UI definition and display observer code
live in `bmc-nix-init/` (the library crate) so both binaries share
the same UI. The mock binary uses Slint's windowed backend to preview
renders on desktop, while the openwrt binary uses the DRM backend.

**WiFi scope:** If no WiFi is configured, the init binary enters AP
mode (via `OpenwrtWifiManager`), shows the AP SSID on display, and
starts a captive portal for WiFi configuration. This reuses the
pattern from `bmc/src/initial_setup.rs`. Once WiFi is configured,
the init binary connects and proceeds with store initialization.

After init completes, the main `bmc` service takes over. The init
binary exits 0.

**Tech Stack:** Rust (tokio, reqwest, clap, ii-net-drv), ARMv7 musl
cross-compilation, Slint (DRM + software renderer), OpenWrt init
service

**Files:**

This is the central logic. It orchestrates the full initialization
flow using `bmc-nix` library functions.

**Step 1: Implement**

```rust
use crate::config::InitConfig;
use crate::state::{InitState, InitStateObserver};
use bmc_nix::profile;
use bmc_nix::store;
use bmc_nix::types::ServersConfig;
use std::path::Path;

/// Check if the Nix store is already initialized.
///
/// Uses a two-stage check matching the concept doc
/// (`nix-daemon-overview.md:24-26`):
/// 1. Check the volatile activation sentinel (`/tmp/nix_activated`)
///    — if present, activation already ran this boot.
/// 2. Check the persistent `current` symlink in the profile dir
///    — if present, the store was initialized on a previous boot.
///
/// The U-Boot `nix_init` variable is checked separately via
/// `is_store_ever_initialized()` for the BOS upgrade flow.
pub fn is_store_initialized(config: &InitConfig) -> bool {
    config.activation_sentinel.exists()
        || config.profile_dir.join("current").exists()
}

/// Check if the store was ever initialized (persists across reboots).
/// Reads the U-Boot environment variable `nix_init`.
pub fn is_store_ever_initialized(config: &InitConfig) -> bool {
    std::process::Command::new("fw_printenv")
        .arg("-n")
        .arg(&config.uboot_sentinel_var)
        .output()
        .ok()
        .map_or(false, |output| {
            output.status.success()
                && String::from_utf8_lossy(&output.stdout).trim() == "1"
        })
}

/// Set the persistent U-Boot init marker after first-time init.
fn set_uboot_init_marker(config: &InitConfig) -> Result<(), InitError> {
    let status = std::process::Command::new("fw_setenv")
        .arg(&config.uboot_sentinel_var)
        .arg("1")
        .status()
        .map_err(|e| InitError::config(format!(
            "failed to run fw_setenv: {e}"
        )))?;
    if !status.success() {
        return Err(InitError::config(format!(
            "fw_setenv {var} 1 failed with {status}",
            var = config.uboot_sentinel_var
        )));
    }
    Ok(())
}

/// Check if a profile exists but hasn't been activated yet.
/// This happens after tarball extraction (tarball doesn't set
/// `current` symlink).
pub fn has_unactivated_profile(config: &InitConfig) -> bool {
    !config.profile_dir.join("current").exists()
        && has_any_generation(&config.profile_dir)
}

/// Check if any generation directories exist.
fn has_any_generation(profile_dir: &Path) -> bool {
    std::fs::read_dir(profile_dir)
        .ok()
        .map(|entries| {
            entries.filter_map(Result::ok).any(|e| {
                e.file_name()
                    .to_str()
                    .map_or(false, |name| name.ends_with("-link"))
            })
        })
        .unwrap_or(false)
}

/// Run the full initialization flow.
///
/// Flow:
/// 1. Check if store is initialized → exit early silently
/// 2. If profile exists but not activated → activate and exit
/// 3. Check network connectivity (v1: fail if no WiFi)
/// 4. Fetch factory index
/// 5. Download tarball (with progress)
/// 6. Extract tarball
/// 7. Activate initial profile
/// 8. Set U-Boot marker + write activation sentinel
///
/// **Display note:** Do not show anything on screen until init
/// is actually needed (per `nix-openwrt-services.md:38`). The
/// `Checking` and `AlreadyInitialized` states are logged but
/// should NOT initialize the display.
pub async fn run_init<W: WifiManager>(
    config: &InitConfig,
    wifi: &W,
    observer: &dyn InitStateObserver,
) -> Result<(), InitError> {
    // Step 1: Check if already initialized
    // Do NOT call observer here — display should not be shown
    tracing::info!("checking store initialization status");
    if is_store_initialized(config) {
        tracing::info!("store already initialized, exiting");
        return Ok(());
    }

    // Step 2: Check for unactivated profile (post-tarball-extraction)
    if has_unactivated_profile(config) {
        // Verify generation integrity before activation
        let gen_path = find_latest_generation_path(&config.profile_dir)?;
        if !gen_path.join("manifest").exists() {
            return Err(InitError::activation(format!(
                "generation {} has no manifest — tarball extraction \
                 may have been interrupted",
                gen_path.display()
            )));
        }
        observer.on_state_change(&InitState::Activating);
        activate_latest_generation(config).await?;
        write_sentinel(config)?;
        set_uboot_init_marker(config)?;
        observer.on_state_change(&InitState::Done);
        return Ok(());
    }

    // Step 3: Check network connectivity, start AP mode if needed
    if !wifi.is_connected().await.map_err(InitError::Wifi)? {
        // No WiFi — enter AP mode and wait for user to configure
        let ap_ssid = wifi.start_ap_mode().await.map_err(InitError::Wifi)?;
        observer.on_state_change(&InitState::NoWifi {
            ap_ssid: ap_ssid.clone(),
        });
        wifi.wait_for_connection().await.map_err(InitError::Wifi)?;
        observer.on_state_change(&InitState::Connecting);
    }

    // Step 4: Read configuration
    let servers_json = std::fs::read_to_string(&config.servers_config_path)
        .map_err(|e| InitError::config(format!(
            "failed to read {}: {e}", config.servers_config_path.display()
        )))?;
    let servers_config: ServersConfig = serde_json::from_str(&servers_json)
        .map_err(|e| InitError::config(format!("invalid servers.json: {e}")))?;
    let bos_version = config.read_bos_version()
        .map_err(|e| InitError::config(format!("failed to read BOS version: {e}")))?;

    // Step 5: Fetch factory index and download tarball
    observer.on_state_change(&InitState::FetchingIndex);
    let client = reqwest::Client::new();

    let progress_observer = DownloadProgressAdapter { observer };
    let init_result = store::init_store(
        &client,
        &servers_config.factory,
        &bos_version,
        Some(&progress_observer),
    ).await.map_err(|e| {
        // Check for "no matching tarball" specifically
        // TODO(future): trigger BOS upgrade if no tarball matches,
        // per nix-daemon-details.md:62-66. For v1, just report
        // error with available BOS versions.
        InitError::Store(e)
    })?;

    // Step 6-7: Activate
    observer.on_state_change(&InitState::Activating);
    activate_latest_generation(config).await?;

    // Step 8: Set persistent markers
    write_sentinel(config)?;
    set_uboot_init_marker(config)?;
    observer.on_state_change(&InitState::Done);

    Ok(())
}

/// Find the path to the latest (highest-numbered) generation.
fn find_latest_generation_path(
    profile_dir: &Path,
) -> Result<std::path::PathBuf, InitError> {
    // Reuses next_generation_number logic: latest = max(N)
    let gen_number = profile::next_generation_number(profile_dir)
        .map_err(|e| InitError::activation(format!(
            "failed to scan generations: {e}"
        )))?;
    let latest = gen_number.saturating_sub(1);
    if latest == 0 {
        return Err(InitError::activation(
            "no generations found in profile directory",
        ));
    }
    Ok(profile_dir.join(format!("{latest}-link")))
}

/// Activate the latest generation in the profile directory.
async fn activate_latest_generation(
    config: &InitConfig,
) -> Result<(), InitError> {
    let _lock = profile::lock_profile(&config.profile_dir)
        .await
        .map_err(|e| InitError::activation(format!("lock failed: {e}")))?;

    let gen_path = find_latest_generation_path(&config.profile_dir)?;
    let latest = gen_path.file_name()
        .and_then(|n| n.to_str())
        .and_then(|n| n.strip_suffix("-link"))
        .and_then(|n| n.parse::<u32>().ok())
        .ok_or_else(|| InitError::activation(
            "cannot parse generation number from path",
        ))?;

    // read_manifest is sync (not async)
    let manifest = bmc_nix::manifest::read_manifest(&gen_path)
        .map_err(|e| InitError::activation(format!(
            "failed to read manifest: {e}"
        )))?;

    let generation = bmc_nix::types::ProfileGeneration {
        number: latest,
        path: gen_path,
        manifest,
    };

    // activate_profile runs the entrypoint script, which sets
    // the `current` symlink via the `zzz-link-current` activation
    // script. The init binary does NOT set `current` directly.
    profile::activate_profile(&config.profile_dir, &generation)
        .await
        .map_err(|e| InitError::activation(format!(
            "activation failed: {e}"
        )))?;

    Ok(())
}

/// Write the activation sentinel file.
fn write_sentinel(config: &InitConfig) -> Result<(), InitError> {
    std::fs::write(&config.activation_sentinel, "1")
        .map_err(|e| InitError::activation(format!(
            "failed to write sentinel {}: {e}",
            config.activation_sentinel.display()
        )))
}

/// Adapter to bridge store::DownloadProgress to InitStateObserver.
struct DownloadProgressAdapter<'a> {
    observer: &'a dyn InitStateObserver,
}

impl store::DownloadProgress for DownloadProgressAdapter<'_> {
    fn on_bytes_downloaded(&self, downloaded: u64, total: Option<u64>) {
        self.observer.on_state_change(&InitState::Downloading {
            downloaded_bytes: downloaded,
            total_bytes: total,
        });
    }
    fn on_phase(&self, phase: &str) {
        match phase {
            "extracting" => {
                self.observer.on_state_change(&InitState::Extracting);
            }
            _ => {}
        }
    }
}

/// WiFi manager trait — abstracted for mock vs real hardware.
///
/// **Object safety:** This trait must be usable as `&dyn WifiManager`
/// (passed to `run_init`). Native `async fn` in traits (RPITIT) is
/// NOT object-safe. Two options:
///
/// **Option A (recommended for v1):** Make `run_init` generic over
/// `W: WifiManager` instead of taking `&dyn WifiManager`. This
/// avoids the object-safety issue entirely and has zero overhead:
///
/// ```rust
/// pub async fn run_init<W: WifiManager>(
///     config: &InitConfig,
///     wifi: &W,
///     observer: &dyn InitStateObserver,
/// ) -> Result<(), InitError> { ... }
/// ```
///
/// **Option B:** Use `async_trait` or `Pin<Box<dyn Future>>` return
/// types to make the trait object-safe. This adds heap allocation
/// per call but allows `&dyn WifiManager`. Only needed if the trait
/// must be stored in a heterogeneous collection.
///
pub trait WifiManager: Send + Sync {
    /// Check if the device has an active network connection.
    fn is_connected(&self) -> impl std::future::Future<Output = Result<bool, WifiError>> + Send;

    /// Start WiFi AP mode for device setup.
    /// Returns the AP SSID.
    fn start_ap_mode(&self) -> impl std::future::Future<Output = Result<String, WifiError>> + Send;

    /// Wait for the user to configure WiFi via the captive portal.
    fn wait_for_connection(&self) -> impl std::future::Future<Output = Result<(), WifiError>> + Send;
}

#[derive(Debug, thiserror::Error)]
pub enum WifiError {
    #[error("WiFi operation failed: {0}")]
    OperationFailed(String),
    #[error("WiFi not supported: {0}")]
    NotSupported(String),
}

#[derive(Debug, thiserror::Error)]
pub enum InitError {
    #[error("configuration error: {message}")]
    Config {
        message: String,

**Step 4: Create Slint state observer with proper threading**

**Threading model:** The Slint event loop and tokio runtime run on
separate threads. The main thread runs `slint::run_event_loop()`
which blocks. The tokio runtime runs on a separate thread spawned
before the event loop starts:

```rust
// In main.rs (openwrt binary):
// 1. Create Slint window
let window = InitWindow::new().expect("BUG: slint init");
let observer = SlintObserver::new(&window);

// 2. Spawn tokio runtime on a background thread
let rt = tokio::runtime::Runtime::new()?;
let weak = window.as_weak();
rt.spawn(async move {
    if let Err(e) = run_init(&config, &wifi, &observer).await {
        tracing::error!("init failed: {e}");
    }
    // Signal Slint to quit after init completes
    let _ = slint::invoke_from_event_loop(move || {
        if let Some(w) = weak.upgrade() {
            w.hide().ok();
        }
        slint::quit_event_loop().ok();
    });
});

// 3. Run Slint event loop on main thread (blocks)
slint::run_event_loop()?;
```

Slint property setters MUST be called from the Slint event loop
thread. Since `run_init()` runs in a tokio async context, the
observer must marshal state changes to the event loop.

Use `slint::invoke_from_event_loop()` to safely update properties
from any thread:

```rust
// bmc-nix-init-openwrt/src/display.rs
use bmc_nix_init::state::{InitState, InitStateObserver};

slint::include_modules!();

pub struct SlintObserver {
    window: slint::Weak<InitWindow>,
}

impl SlintObserver {
    pub fn new(window: &InitWindow) -> Self {
        Self {
            window: window.as_weak(),
        }
    }
}

impl InitStateObserver for SlintObserver {
    fn on_state_change(&self, state: &InitState) {
        let state = state.clone();
        let weak = self.window.clone();
        // Marshal to the Slint event loop thread to avoid
        // threading panics. This is safe to call from any thread.
        slint::invoke_from_event_loop(move || {
            let Some(window) = weak.upgrade() else { return };
            match &state {
                InitState::FetchingIndex => {
                    window.set_status_text(
                        "Checking for updates...".into(),
                    );
                }
                InitState::Downloading {
                    downloaded_bytes,
                    total_bytes,
                } => {
                    let mb = *downloaded_bytes as f64 / 1_048_576.0;
                    if let Some(total) = total_bytes {
                        let total_mb = *total as f64 / 1_048_576.0;
                        window.set_status_text(
                            format!(
                                "Downloading: {mb:.1} / {total_mb:.1} MB"
                            )
                            .into(),
                        );
                        window.set_progress(
                            *downloaded_bytes as f32 / *total as f32,
                        );
                    } else {
                        window.set_status_text(
                            format!("Downloading: {mb:.1} MB").into(),
                        );
                    }
                    window.set_show_progress(true);
                }
                InitState::Extracting => {
                    window.set_status_text(
                        "Installing packages...".into(),
                    );
                    window.set_show_progress(false);
                }
                InitState::Activating => {
                    window.set_status_text("Finalizing...".into());
                }
                InitState::Done => {
                    window.set_status_text("Ready!".into());
                }
                InitState::Error { message, .. } => {
                    window.set_status_text("Error".into());
                    window.set_detail_text(message.clone().into());
                }
                // Checking and AlreadyInitialized are not shown
                // on the display (per nix-openwrt-services.md:38)
                _ => {}
            }
        })
        .expect("BUG: event loop should be running");
    }
}
```

## Subtask 6: OpenWrt service

### Task 6.1: Document the OpenWrt service

The actual OpenWrt service file lives in the `bos-packages` or
`openwrt` repository (cross-repo, Stage 10). For this stage, document
the service behavior and provide a reference implementation.

**Service behavior** (from `nix-openwrt-services.md`):

The `bmc-nix-initializer` service:
1. Runs as a regular service (not in `boot()` phase)
2. Runs after the boot has finalized
3. Checks if the store is initialized:
   - If `/tmp/nix_activated` (underscore) exists → exit 0
   - If `current` symlink exists → exit 0
4. If not initialized:
   - If profile generation exists but no `current` → activate and exit
   - Otherwise → full init flow (WiFi, download, extract, activate)
5. Does not show anything on screen until init is actually needed
6. The service binary is statically linked — it does NOT depend on
   `/nix/store` content

**Reference init script:**

```bash
#!/bin/sh /etc/rc.common
# /etc/init.d/bmc-nix-init
START=90
USE_PROCD=1

start_service() {
    procd_open_instance
    procd_set_param command /usr/bin/bmc-nix-init \
        --servers-config /etc/nix-upgrade/servers.json \
        --bos-version-path /etc/bos-version \
        --profile-dir /nix/var/nix/gcroots/profiles/bmc
    # respawn: threshold=60s, timeout=5s, retry=5
    # (60s is more reasonable for user-facing init than 3600s)
    procd_set_param respawn 60 5 5
    procd_set_param stdout 1
    procd_set_param stderr 1
    procd_close_instance
}
```

**Key points:**
- `START=90` — runs after most other services
- `respawn` — restart on failure (3600s threshold, 5 retries)
- The binary exits 0 when store is initialized (service stops)

## Known Risks

1. **Slint static linking complexity** — Slint with DRM + musl may
   require custom build flags or patches, particularly `libdrm`
   static linking. Mitigation: check if `bmc-openwrt` has
   extractable `linux_drm_platform` code.

2. **WiFi AP mode complexity** — The AP + captive portal flow
   requires pulling in `ii-net-drv` and reusing the WiFi setup
   pattern from `bmc/src/initial_setup.rs`. Mitigation: study
   the existing `initial_setup.rs` implementation closely and
   extract shared logic where possible.

3. **Cross-repo coordination** — The actual OpenWrt service file
   lives in `bos-packages`. This stage only documents the service;
   Stage 10 implements it. Ensure the binary API (CLI args, exit
   codes) is stable before Stage 10.

4. **Tarball size and download time** — On slow WiFi, the tarball
   download could take significant time. The progress bar helps UX.
   For v1, no resumable downloads — a failed download retries from
   scratch via procd respawn.

5. **BOS version mismatch** — If no factory tarball matches the
   current BOS version, the concept doc (`nix-daemon-details.md:62`)
   specifies triggering a BOS firmware upgrade (sysupgrade + reboot).
   **v1: not implemented.** The init binary reports an error with the
   BOS version and available factory versions. A future iteration
   should add the BOS upgrade path.

6. **Missing services (out of scope)** — The full Nix integration
   design (`nix-openwrt-services.md`) specifies several services
   beyond the init binary:
   - `nix-factory-reset` — wipes Nix store and triggers re-init
   - `nix-activator` — runs activation scripts on boot
   - `nix-service-orchestrator` — manages Nix-installed services
   - `nix-service-collection-hook` — collects service definitions

   These are NOT implemented in Stage 7. They belong to later stages
   (Stage 8: daemon integration, Stage 10: OpenWrt service). The
   init binary only handles first-time store bootstrapping. Document
   this boundary clearly: after `bmc-nix-init` exits 0, the main
   `bmc` service takes over. The activator and orchestrator will be
   integrated when the upgrade daemon (Stage 8) is implemented.

7. **Stage 5 API stability** — This stage depends on Stage 5 APIs
   (`store::init_store()`, `manifest::read_manifest()`,
   `store::DownloadProgress` trait, `ServersConfig` type) that do
   not exist yet. If their signatures change during Stage 5
   implementation, this plan's call sites will need updating.
