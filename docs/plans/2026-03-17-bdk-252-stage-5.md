**Conflict resolution algorithm** (from nix-concepts.md):
1. If installed, first look on same server (`installed_from`)
2. Pick versions respecting pin strategy
3. From remaining, choose latest version
4. On ties, resolve by server priority (lower wins)
5. If still ambiguous, fail explicitly

**Pin strategy logic** (using `semver` crate):
- `PinStrategy::None` — pick latest
- `PinStrategy::Major` — pick latest within same major version
- `PinStrategy::Minor` — pick latest within same major.minor
- `PinStrategy::Patch` — pick exact same version (effectively no upgrade)

**Error type:**

## Subtask 3: Implement store operations

### Task 3.1: Implement `copy_store_paths()`

**Files:**
- Create: `bmc-nix/src/store.rs`
- Modify: `bmc-nix/src/lib.rs` (add `pub mod store;`)

**Step 1: Design decision**

Store path copying uses `nix copy` from binary caches. The resolved
packages contain `cache_url` and `store_path`. The `nix copy` command
handles NAR download, signature verification, and store registration
in a single step.

The command format:
```bash
nix copy --from <cache_url> <store_path_1> <store_path_2> ...
```

This requires the `nix` binary to be available on the device (it's
included in the init tarball as one of the packages).

**Step 2: Implement**

```rust
/// Copy store paths from binary caches to the local Nix store.
/// Groups packages by cache_url and runs one `nix copy` per cache.
/// Skips paths that already exist in the local store.
///
/// Uses `&impl CommandRunner` (not `&dyn`) because the trait has
/// native async fn (RPITIT) which is not object-safe.
pub async fn copy_store_paths(
    runner: &impl CommandRunner,
    packages: &[ResolvedPackage],
    progress: Option<&dyn CopyProgress>,
) -> Result<(), CopyStorePathsError> { ... }

/// Progress callback for store copy operations.
pub trait CopyProgress: Send + Sync {
    fn on_path_copied(&self, index: u32, total: u32, store_path: &str);
}
```

**Key behaviors:**
- Group packages by `cache_url` to minimize `nix copy` invocations
- Before copying, check if each store path is already registered in
  the Nix store via `nix path-info <store_path>` (using the
  `CommandRunner`). Do NOT use `Path::exists()` — a directory may
  exist on disk but not be registered in the Nix database, or it may
  be an incomplete/corrupt path. `nix path-info` checks the store
  database and validates path integrity. Skip already-present paths
- Run `nix copy --from <cache_url> <store_paths...>` via
  `tokio::process::Command`
- Parse stderr for progress (nix outputs path names as they're copied)
- On failure, return `CopyStorePathsError::NixCommand` with the
  specific command and exit status
- Consider adding a timeout via `tokio::time::timeout()` for each
  `nix copy` invocation — on constrained embedded devices with slow
  networks, `nix copy` can hang indefinitely. The caller (daemon)
  may also impose its own timeout at a higher level

**Error type:**

```rust
#[derive(Debug, thiserror::Error)]

    #[error("store path not available on cache {cache}: {store_path}")]
    StorePathUnavailable { store_path: String, cache: String },
    #[error("nix copy failed: {command}")]
    NixCommand { command: String, #[source] source: std::io::Error },
    #[error("nix copy exited with {status}: {stderr}")]
    NixCopyFailed { status: std::process::ExitStatus, stderr: String },
```

```rust
pub trait CommandRunner: Send + Sync {

        program: &str,
        args: &[&str],

}

/// Default implementation using tokio::process::Command.
pub struct TokioCommandRunner;

impl CommandRunner for TokioCommandRunner {
```

```rust
/// Given the current profile manifest and a merged index, produce
/// a list of resolved packages with versions bumped to what the
/// index offers. Respects the `pinned` strategy of each package.
///
/// - Packages in the manifest that are missing from the index are
///   kept at current version and reported as stale.
/// - `add_packages` are new packages to install.
/// - `remove_packages` are package names to remove from the profile.
///   Uses `&[String]` (not `&[ManifestPackage]`) because the name is
///   needed for matching and `ManifestPackage` doesn't carry its own
///   name — it's the key in `Manifest.packages`.
pub fn compute_upgrade_plan(
    current: &Manifest,
    merged: Option<&MergedIndex>,
    add_packages: &[ResolvedPackage],
    remove_packages: &[String],
) -> Result<UpgradePlan, ComputeUpgradePlanError> { ... }
```

**Algorithm:**
1. For each `(name, pkg)` in current manifest:
   - If `name` is in `remove_packages` list, add to `removed`, skip
   - If `merged` is `Some`, try `resolve_installed_package()`
     - If found and version differs, add to `changed`
     - If found and version same, keep as-is
     - If not found, add to `stale`, keep current version
   - If `merged` is `None`, keep current version
2. For each package in `add_packages`:
   - If already in manifest, treat as upgrade
   - If new, add to `added`
3. Build final `packages` list: all kept + changed + added
4. Return `UpgradePlan` with all categorized changes

```rust
    ResolveError {
        name: String,

    },
}
```

```rust
/// Convert a manifest package back to a resolved package.
///
/// This is lossy — `ManifestPackage` does not store `cache_url`,
/// only `cache` (name). For kept packages that are not being
/// upgraded, the `cache_url` is set to empty string. The caller
/// should only pass this to `build_profile` (which does not need
/// `cache_url`), NOT to `copy_store_paths` (which needs it for
/// downloading). Only packages that are actually changing should
/// go through `copy_store_paths`.
fn manifest_package_to_resolved(
    name: &str,
    mp: &ManifestPackage,
) -> ResolvedPackage {
    ResolvedPackage {
        name: name.to_owned(),
        version: mp.version.clone(),
        store_path: mp.store_path.clone(),
        cache_url: String::new(), // not available from manifest
        category: mp.category.clone(),
        description: mp.description.clone(),
        upgrade_strategy: mp.upgrade_strategy.clone(),
        install_strategy: mp.install_strategy.clone(),
        installed_by: mp.installed_by.clone(),
        installed_from: mp.installed_from.clone(),
        pinned: mp.pinned.clone(),
    }
}

/// Merge the current manifest with new packages.
/// New packages replace existing entries by name.
pub fn merge_installed_with_new(
    current: &Manifest,
    packages: &[ResolvedPackage],
) -> Vec<ResolvedPackage> {
    let mut result: BTreeMap<String, ResolvedPackage> = current
        .packages
        .iter()
        .map(|(name, mp)| (name.clone(), manifest_package_to_resolved(name, mp)))
        .collect();

    for pkg in packages {
        result.insert(pkg.name.clone(), pkg.clone());
    }

    result.into_values().collect()
}
```

**Step 2: Implement `apply_profile_change()`**

This is the main orchestration function (from `bmc-nix.md:644-680`):

```rust
/// Apply already-resolved packages into the current profile.
/// The caller is responsible for fetching indexes, resolving
/// package names, and running checker packages beforehand.
///
/// `current` is the active profile generation (used to merge
/// existing manifest packages with the upgrade plan). Pass
/// `None` for first-time installation.
pub async fn apply_profile_change(
    current: Option<&ProfileGeneration>,
    profile_dir: &Path,
    gc_config: &GcConfig,
    plan: &UpgradePlan,
    activate: bool,
    progress: Option<&dyn UpgradeProgress>,
) -> Result<InstallResult, InstallError> {
    // 1. Acquire profile lock
    let _lock = profile::lock_profile(profile_dir)
        .await
        .map_err(InstallError::Lock)?;

    // 2. Merge existing manifest with new packages
    let all_packages = if let Some(gen) = current {
        let manifest = manifest::read_manifest(&gen.path)?;
        merge_installed_with_new(&manifest, &plan.packages)
    } else {
        plan.packages.clone()
    };

    // 3. Copy store paths — ONLY packages from the upgrade plan
    // (which have valid cache_url). Kept packages from the manifest
    // have empty cache_url and must NOT be passed to copy_store_paths.
    if let Some(p) = progress { p.on_phase("copying"); }
    store::copy_store_paths(
        &store::TokioCommandRunner,
        &plan.packages,
        None,
    ).await?;

    // 4. Build new profile generation
    if let Some(p) = progress { p.on_phase("building"); }
    // Note: next_generation_number is synchronous (not async)
    let gen_number = profile::next_generation_number(profile_dir)?;
    let generation = profile::build_profile(
        profile_dir,
        gen_number,
        &all_packages,
        "hooks",
        None,
    ).await?;

    // 5. Optionally activate
    if activate {
        if let Some(p) = progress { p.on_phase("activating"); }
        profile::activate_profile(profile_dir, &generation)
            .await?;  // ActivationError → InstallError::Activation via #[from]
    }

    // 6. GC old generations
    gc::cleanup_generations(profile_dir, gc_config).await?;

    Ok(InstallResult {
        strategies: StrategySummary::from_packages(&all_packages),
        generation,
    })
}
```

**Error type:**

Each variant must use a distinct source type — `#[from]` cannot be
applied multiple times for the same type. The existing code returns:
- `lock_profile()` → `BuildProfileError`
- `build_profile()` → `BuildProfileError`
- `activate_profile()` → `ActivationError` (NOT `BuildProfileError`)

Since `lock_profile` and `build_profile` share `BuildProfileError`,
only one can use `#[from]`; the other must use `#[source]` with a
manual `.map_err()` at the call site:

```rust
#[derive(Debug, thiserror::Error)]
pub enum InstallError {
    #[error("profile lock failed: {0}")]
    Lock(#[source] profile::BuildProfileError),
    #[error(transparent)]
    CopyStorePaths(#[from] store::CopyStorePathsError),
    #[error(transparent)]
    BuildProfile(#[from] profile::BuildProfileError),
    #[error("activation failed: {0}")]
    Activation(#[from] activation::ActivationError),
    #[error(transparent)]
    CleanupGenerations(#[from] gc::CleanupGenerationsError),
    #[error(transparent)]
    ReadManifest(#[from] manifest::ReadManifestError),
}
```

Note: `Lock` uses `#[source]` instead of `#[from]` because
`BuildProfileError` already has a `#[from]` via `BuildProfile`.
`Activation` can use `#[from]` because `ActivationError` (from
`bmc-nix/src/activation.rs`) is a distinct type not shared by other
variants. The `ReadManifest` variant covers manifest reading needed
by `merge_installed_with_new`.

```rust
/// Remove old profile generations according to GC policy.
///
/// Keeps:
/// - The current generation (pointed to by `current` symlink)
/// - Protected generations from `gc_config.protected_generations`
/// - The most recent `gc_config.keep_generations` generations
/// - Generations newer than `gc_config.keep_days` days
///
/// Removes everything else by deleting the generation directory.
///
/// **Note:** This function is sync (no await points) despite being
/// marked `async`. It is `async` only for API consistency with
/// `apply_profile_change()` which calls it from an async context.
/// The implementer may choose to make it sync (`fn` instead of
/// `async fn`) and call it directly — both approaches are valid.
pub async fn cleanup_generations(
    profile_dir: &Path,
    gc_config: &GcConfig,
) -> Result<(), CleanupGenerationsError> { ... }

/// Run `nix-collect-garbage` to remove unreachable store paths.
/// This frees disk space after generations have been deleted.
///
/// **When to call:** `collect_garbage()` is NOT called inside
/// `apply_profile_change()` because it is expensive (scans the
/// entire store). Instead, the daemon should call it on a
/// periodic timer (e.g. daily) or when disk space is low. The
/// `cleanup_generations()` call in `apply_profile_change()`
/// removes generation directories, making their store paths
/// unreachable — but the actual disk space is only freed when
/// `collect_garbage()` runs later.
pub async fn collect_garbage() -> Result<(), CollectGarbageError> {
    let status = tokio::process::Command::new("nix-collect-garbage")
        .status()
        .await
        .map_err(CollectGarbageError::NixCommand)?;
    if !status.success() {
        return Err(CollectGarbageError::NixCommand(
            std::io::Error::new(
                std::io::ErrorKind::Other,
                format!("nix-collect-garbage exited with {status}"),
            ),
        ));
    }
    Ok(())
}
```

**Algorithm for `cleanup_generations()`:**
1. List all `N-link` directories in `profile_dir`
2. Parse generation numbers
3. Read `current` symlink to find active generation
4. Build keep set: current + protected + most recent
   `keep_generations` + those newer than `keep_days`
5. Remove directories not in keep set
6. Log each removal via `tracing::info!`

**Note on `keep_days`:** Generation directories do not store creation
timestamps in the manifest. Use filesystem `mtime` of the generation
directory to determine age. While this is fragile (any file operation
inside the directory can update it), it is the pragmatic approach used
by Nix's own `nix-collect-garbage` for generations. Document this
limitation in the function's doc comment.
