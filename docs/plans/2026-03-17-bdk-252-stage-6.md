# BDK-252 Stage 6: Deployment Indexes — Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build the Nix derivations and tooling that produce final
deployment indexes — both the runtime upgrade index
(`miniminer-index.json`) and the factory initialization index
(`factory.json`). Stage 2 already implemented `mkIndex.nix`
and `init-artifacts.nix` for the init tarball. This stage ensures those
produce complete, spec-compliant indexes and adds factory index
generation.

**Prerequisites:** Stages 1-4 complete — init tarball working,
autoPatchelfHook rpath. **No dependency on Stage 5.** This stage is
pure Nix derivation and validation work. The only shared touch point
is `FactoryIndex`/`FactoryTarball` types in `bmc-nix/src/types.rs` —
if Stage 5 hasn't added them yet, this stage adds them directly
(see Task 4.2 Step 3). Both stages can be implemented in parallel.

**What already exists:**
- `nix/mkIndex.nix` — generates `index.json` from a package list. Uses
  `pkgs.writeText` + `builtins.toJSON`. Accepts `packages`, `caches`,
  `indexes`, `commit` parameters.
- `nix/mkTarball.nix` — generates init tarball, calls `mkIndex`
  internally for the temp index used during profile building.
- `nix/init-artifacts.nix` — wires packages (core, nix, digital-clock,
  flip-clock) into `mkIndex` and `mkTarball`. Produces
  `init-index-armv7` and `init-tarball-armv7`.
- `nix/packages.nix` — single source of truth for package definitions
  with metadata (name, version, category, description, strategies).
- `workspace.nix` — build infrastructure, package outputs.
- `bmc-nix/src/types.rs` — `PackageIndex`, `PackageEntry`,
  `CacheEntry`, `Provenance` types for parsing. `FactoryIndex` and
  `FactoryTarball` types may or may not exist yet (they are also
  defined in Stage 5 Task 1.1). If not present, add them in Task 4.2
  Step 3 of this stage.
- `bmc-nix/src/index.rs` — `resolve_all_from_index()` (from Stage 1).
  The round-trip test in Task 4.2 only needs this function.

**What this stage adds/changes:**
1. Ensure `mkIndex.nix` produces a complete `miniminer-index.json`
   usable for runtime upgrades (validate against concept doc schema).
2. Add `mkFactoryIndex.nix` — collects `metadata.json` from tarball
   builds and produces `factory.json`.
3. Validation tooling — JSON schema check scripts and round-trip test
   with `bmc-nix` index parsing.
4. Wire factory index into flake outputs.

**Tech Stack:** Nix (derivations, builtins.toJSON), Python or bash for
schema validation, `bmc-nix` for round-trip testing

**Step 2: Check against the concept doc schema**

The `miniminer-index.json` schema from `nix-concepts.md:112-151`:

Required fields:
- `version: 1` (integer)
- `provenance: { commit: "<hash>" }` (object with string)
- `indexes: [...]` (array of URLs, may be empty)
- `caches: [{ name, cache_url, cache_key }]` (array)
- `packages: [{ name, version, cache, store_path, category,
  description, upgrade_strategy, install_strategy }]` (array)

Per-package fields:
- `name` — string, required
- `version` — string, required
- `cache` — string or null (defaults to first cache name if absent)
- `store_path` — string, required, must start with `/nix/store/`
- `category` — string or null
- `description` — string or null
- `upgrade_strategy` — `"reboot"` or null
- `install_strategy` — `"reboot"` or null

Verify:
1. All required top-level fields present
2. `provenance.commit` populated (not empty string or "dirty" in CI)
3. All packages have `store_path` starting with `/nix/store/`
4. `upgrade_strategy` and `install_strategy` serialize as `"reboot"`
   or `null` (never JSON `false`)

**Step 3: Verify — this is likely a non-issue**

The actual `packages.nix` already uses `null` (not `false`) for

## Subtask 2: Implement `mkFactoryIndex.nix`

### Task 2.1: Design the factory index generation

**Background:** The factory index (`factory.json`) lists
tarballs for device initialization, one per BOS version (from
`nix-concepts.md:180-208`):

```json
{
  "version": 1,
  "tarballs": [
    {
      "bos_version": "26.02",
      "download_url": "https://cache.braiins.com/v1/miniminer-nix-26.02.tar.gz",
      "profile_path": "/nix/var/nix/gcroots/profiles/bmc"
    }
  ]
}
```

**Key design decisions:**

1. **`download_url` is NOT known at build time** — it depends on where
   the tarball is ultimately published. The Nix derivation produces
   `metadata.json` alongside the tarball, which contains `bos_version`,
   `profile_path`, and `tarball_name`. The factory index is assembled
   by external tooling (CI script) that:
   - Collects `metadata.json` from one or more tarball builds
   - Adds the `download_url` based on the publishing location
   - Writes `factory.json`

2. **Single BOS version initially** — for now, we build only one
   tarball (BOS 26.02). The factory index will have one entry.
   Multi-version support comes when we have multiple BOS versions
   in production.

3. **Build vs. external tooling** — the factory index cannot be a
   pure Nix derivation because `download_url` is external information.
   We provide:
   - A Nix helper (`mkFactoryIndex.nix`) that generates the JSON given
     a list of tarball entries (for testing and local use)
   - A CI script (`scripts/build-factory-index.sh`) that assembles the
     index from published tarballs

```nix
# nix/mkFactoryIndex.nix
#
# Generates a factory.json from a list of tarball entries.
# Each entry provides bos_version, download_url, and profile_path.
#
# This is used for:
# - Local testing (with file:// URLs pointing to built tarballs)
# - CI integration (with real HTTPS URLs)
{ pkgs }:
{ tarballs  # [ { bos_version; download_url; profile_path; } ]
}:
let
  factoryIndex = {
    version = 1;
    # `map` is a Nix builtin — no `lib` import needed.
    tarballs = map (t: {
      inherit (t) bos_version download_url profile_path;
    }) tarballs;
  };
  json = builtins.toJSON factoryIndex;
in
pkgs.writeTextDir "factory.json" json
```

### Task 2.3: Implement CI helper script

**Files:**
- Create: `scripts/build-factory-index.sh`

**Step 1: Implement**

```bash
#!/usr/bin/env bash
# Build factory.json from metadata.json files.
#
# Usage:
#   ./scripts/build-factory-index.sh \
#     --base-url https://cache.braiins.com/v1 \
#     --metadata result/metadata.json \
#     [--metadata other/metadata.json] \
#     --output factory.json
#
# Each metadata.json contains:
#   { "bos_version": "26.02",
#     "profile_path": "/nix/var/nix/gcroots/profiles/bmc",
#     "tarball_name": "nix-26.02.tar.gz" }
#
# The script constructs download_url as:
#   <base_url>/<tarball_name>
set -euo pipefail

base_url=""
metadata_files=()
output=""

while [[ $# -gt 0 ]]; do
    case "$1" in
        --base-url) base_url="$2"; shift 2 ;;
        --metadata) metadata_files+=("$2"); shift 2 ;;
        --output) output="$2"; shift 2 ;;
        *) echo "Unknown option: $1" >&2; exit 1 ;;
    esac
done

if [[ -z "$base_url" || ${#metadata_files[@]} -eq 0 || -z "$output" ]]; then
    echo "Usage: $0 --base-url URL --metadata FILE [--metadata FILE...] --output FILE" >&2
    exit 1
fi

# Build the factory index using a single Python invocation.
# Pass all metadata files and base URL as arguments to avoid
# shell injection via string interpolation.
python3 - "$base_url" "$output" "${metadata_files[@]}" <<'PYEOF'
import json
import sys

base_url = sys.argv[1]
output_path = sys.argv[2]
metadata_files = sys.argv[3:]

tarballs = []
for meta_file in metadata_files:
    with open(meta_file) as f:
        meta = json.load(f)
    tarballs.append({
        "bos_version": meta["bos_version"],
        "download_url": f"{base_url}/{meta['tarball_name']}",
        "profile_path": meta["profile_path"],
    })

factory = {"version": 1, "tarballs": tarballs}
with open(output_path, "w") as f:
    json.dump(factory, f, indent=2)
print(f"Written {len(tarballs)} tarballs to {output_path}")
PYEOF
```

### Task 4.1: Create JSON schema validation script

**Files:**
- Create: `scripts/validate-nix-indexes.sh`

**Step 1: Implement**

```bash
#!/usr/bin/env bash
# Validate Nix index JSON files against the concept doc schema.
#
# Usage:
#   ./scripts/validate-nix-indexes.sh [--index FILE] [--factory FILE]
set -euo pipefail

index_file=""
factory_file=""

while [[ $# -gt 0 ]]; do
    case "$1" in
        --index) index_file="$2"; shift 2 ;;
        --factory) factory_file="$2"; shift 2 ;;
        *) echo "Unknown option: $1" >&2; exit 1 ;;
    esac
done

errors=0

validated=0

if [[ -n "$index_file" ]]; then
    echo "Validating index: $index_file"
    python3 - "$index_file" <<'PYEOF' || errors=$((errors + 1))
import json, sys

with open(sys.argv[1]) as f:
    idx = json.load(f)

errors = []

# Top-level fields
if idx.get('version') != 1:
    errors.append(f'version must be 1, got {idx.get("version")}')
if 'provenance' not in idx:
    errors.append('missing provenance field')
else:
    commit = idx['provenance'].get('commit', '')
    if not commit or commit == 'dirty':
        errors.append(f'provenance.commit must be a valid hash, got "{commit}"')
if not isinstance(idx.get('indexes', []), list):
    errors.append('indexes must be a list')
if not isinstance(idx.get('caches', []), list):
    errors.append('caches must be a list')
if not isinstance(idx.get('packages', []), list):
    errors.append('packages must be a list')

# Cache fields
for i, c in enumerate(idx.get('caches', [])):
    for field in ('name', 'cache_url', 'cache_key'):
        if field not in c:
            errors.append(f'cache[{i}] missing {field}')

# Package fields
VALID_STRATEGIES = ('reboot',)  # extend when new strategies are added
for i, p in enumerate(idx.get('packages', [])):
    for field in ('name', 'version', 'store_path'):
        if field not in p:
            errors.append(f'package[{i}] missing {field}')
    sp = p.get('store_path', '')
    if sp and not sp.startswith('/nix/store/'):
        errors.append(f'package[{i}] store_path must start with /nix/store/')
    us = p.get('upgrade_strategy')
    if us is not None and us not in VALID_STRATEGIES:
        errors.append(f'package[{i}] invalid upgrade_strategy: {us}')
    ist = p.get('install_strategy')
    if ist is not None and ist not in VALID_STRATEGIES:
        errors.append(f'package[{i}] invalid install_strategy: {ist}')

if errors:
    for e in errors:
        print(f'  ERROR: {e}', file=sys.stderr)
    sys.exit(1)
else:
    print(f'  OK: {len(idx["packages"])} packages validated')
PYEOF
    validated=$((validated + 1))
fi

if [[ -n "$factory_file" ]]; then
    echo "Validating factory index: $factory_file"
    python3 - "$factory_file" <<'PYEOF' || errors=$((errors + 1))
import json, sys

with open(sys.argv[1]) as f:
    idx = json.load(f)

errors = []

if idx.get('version') != 1:
    errors.append(f'version must be 1, got {idx.get("version")}')
if not isinstance(idx.get('tarballs', []), list):
    errors.append('tarballs must be a list')

for i, t in enumerate(idx.get('tarballs', [])):
    for field in ('bos_version', 'download_url', 'profile_path'):
        if field not in t:
            errors.append(f'tarball[{i}] missing {field}')

if errors:
    for e in errors:
        print(f'  ERROR: {e}', file=sys.stderr)
    sys.exit(1)
else:
    print(f'  OK: {len(idx["tarballs"])} tarballs validated')
PYEOF
    validated=$((validated + 1))
fi

if [[ $validated -eq 0 ]]; then
    echo "ERROR: No files to validate. Use --index or --factory." >&2
    exit 1
fi

if [[ $errors -gt 0 ]]; then
    echo "FAILED: $errors validation errors"
    exit 1
fi
echo "All validations passed."
```

### Task 4.2: Round-trip test with `bmc-nix` index parsing

```rust
/// Round-trip test: read an index JSON file (built by mkIndex.nix),
/// parse it with bmc_nix::types::PackageIndex, resolve all packages,
/// and verify the results are consistent.
#[test]
fn index_json_round_trip() {
    // This test reads a fixture file that mirrors mkIndex output.
    // In CI, this fixture is regenerated from `nix build .#init-index-armv7`.
    let json = include_str!("fixtures/test-index.json");
    let index: bmc_nix::types::PackageIndex = serde_json::from_str(json)
        .expect("BUG: index JSON should parse");

    assert_eq!(index.version, 1);
    assert!(!index.packages.is_empty());

    // Resolve all packages
    let resolved = bmc_nix::index::resolve_all_from_index(&index)
        .expect("BUG: all packages should resolve");

    assert_eq!(resolved.len(), index.packages.len());
    for pkg in &resolved {
        assert!(
            pkg.store_path.starts_with("/nix/store/"),
            "store_path must be a Nix store path: {}",
            pkg.store_path
        );
        assert!(!pkg.name.is_empty());
        assert!(!pkg.version.is_empty());
    }
}
```

```
1. `nix build .#init-index-armv7` → `result/index.json`

        --base-url https://cache.braiins.com/v1 \
        --metadata result/metadata.json \
        --output factory.json`
   d. Upload factory index to cache server

5. Validation:
   `./scripts/validate-nix-indexes.sh \
```

## Known Issues and Discrepancies

1. **Output filename:** `mkIndex.nix` currently produces
   `$out/index.json`. The concept doc (`nix-concepts.md:110`) uses
   `miniminer-index.json` as the runtime URL path.

   **Decision:** Keep `mkIndex.nix` producing `index.json` as the
   derivation output name. The CI upload/publish step renames it to
   `miniminer-index.json` when uploading to the cache server. This
   keeps the build generic (the index is not inherently tied to the
   "miniminer" product name) while the publish step applies the
   product-specific naming. Document this in Task 5.1 (CI flow docs).
   The init tarball uses the index internally as `index.json` — this
   is correct since it's a local path, not a published URL.

2. **Tarball naming:** `mkTarball.nix` produces `nix-${bos_version}.tar.gz`
   (e.g. `nix-26.02.tar.gz`), but the `nix-build.md` spec says
   `miniminer-nix-26.01.tar.gz`. The code is the source of truth here.
   Update `nix-build.md` to match.

3. **Compression format:** The concept doc (`nix-concepts.md:206`)
   says `.tar.xz`, but `mkTarball.nix` and `nix-build.md` both use
   `.tar.gz`. The code is the source of truth. Update the concept doc
   to match.

4. **`FactoryIndex`/`FactoryTarball` types:** These do not exist in
   `bmc-nix/src/types.rs` yet. They are Stage 5 deliverables. If
   Stage 5 is not complete before Stage 6, the types must be added
   as a prerequisite task in this stage.

5. **Fixture staleness:** The round-trip test uses committed fixture
   files that may drift from actual Nix build output. Recommended
   approach: use a hand-crafted minimal fixture (2 packages) that
   only needs updating when the schema changes. A CI step to detect
   drift can be added later.
