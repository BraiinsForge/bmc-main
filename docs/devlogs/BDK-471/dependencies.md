# Dependency audit and intentional pins

Audit date: 2026-10-23, on the BDK-1007 relock with wasmi 2.0 (BDK-1012), reqwest 0.12 (BDK-1013) and zip 9 applied;
every claim re-checked against the crate sources, the lock files and crates.io on 2026-10-26. Ticket: BDK-471. The
commands are listed at the end so the audit can be re-run.

BDK-1007 (2026-10-22/23) relocked every workspace, nixpkgs, the Rust toolchain and mesa, so semver-compatible updates
are already in the lock files. This document records only what a relock cannot do: major bumps, pins and their reasons.

## Re-running the audit

From the worktree root (`nix develop` has none of the cargo plugins; take them from the flake's `pkgs`):

```sh
nix run .#pkgs.cargo-audit -- audit --file <lock>            # each of the six Cargo.lock files
nix develop -c sh -c 'PATH=$(nix build .#pkgs.cargo-edit --print-out-paths --no-link)/bin:$PATH \
  cargo upgrade --dry-run --incompatible allow --verbose'   # per workspace; lists compatible and latest
nix develop -c sh -c 'cd frontend && pnpm outdated'
nix flake metadata --json . | nix run .#pkgs.jq -- '.locks.nodes'
```

`cargo outdated --workspace` cannot run in the root workspace: it copies the tree to a temporary directory and loses the
`tooling/` path dependencies' workspace root. `cargo upgrade --dry-run` from cargo-edit does the same job in place and
writes nothing.
