Widget lifecycle coordination

The coordinator brings process supervision and display state together without coupling them. It sends commands to the widget manager and compositor, while each component remains the sole owner of its own state.

identity instance key process owner widget manager display owner compositor policy owner coordinator

Design goal

Keep the relationship simple

The widget manager does not call the compositor, forward compositor results, or report child PIDs for routing. The compositor does not drive process supervision. The coordinator decides what should happen and issues the corresponding command to each owner.

The one shared startup detail is the Wayland display name passed to a widget process. After launch, the widget identifies itself to the compositor with its canonical instance key. Per-widget spawn, restart, and reconnect no longer require manager–compositor handoffs.

coordinator

Own policy and ordering

Interpret configuration changes, gate initial spawn on compositor receipts, and direct stop, upgrade, and shutdown transitions.

widget manager

Own child processes

Spawn, stop, observe, and restart widget children. Keep restart backoff and pending work local to process supervision.

compositor

Own display state

Register instance keys, accept or reject connections, retain configuration, and attach Wayland clients and surfaces.

Initial start

Registration is complete before spawn

1 · prepare

Validate config, package identity, and viewport; obtain a start permit from the manager.

2 · register

Create or update the compositor record for the canonical widget instance key.

3 · activate

Mark the instance as accepting connections. Both compositor commands return receipts.

4 · await

Wait for both receipts and revalidate that the requested widget is still current.

5 · spawn

Spend the permit and ask the manager to launch the child.

A compositor error prevents a pointless process spawn. The receipt is an ordering boundary, not data passed to the manager: the coordinator consumes it and independently decides whether the manager may proceed.

Connection identity

The widget announces its instance key, not its PID

1widget childConnect to the startup Wayland display and request a widget surface with the canonical instance key.
2compositorParse the key and accept it only when the corresponding record exists and is active.
3compositorAttach the client and surfaces, replacing an obsolete client for the same instance when necessary.
4compositorSend retained parameters, credentials, viewport, and lifecycle state to the newly attached client.

There is no pending PID connection table, peer-credential lookup, generation handoff, or manager event stream. The compositor resolves the announced key directly against the registration it already owns.

Crash recovery

Respawn stays inside the manager

Running

The manager observes child exit, schedules backoff, rereads the package registry, and launches the replacement. The compositor registration remains active, so the replacement reconnects under the same instance key and receives the retained state. The coordinator is not on this per-crash path.

If the WASM host dies, its control connections close and all affected thin processes exit. The manager applies the same supervision independently to each instance; each replacement reconnects directly to the compositor.

Configuration changes

One decision, commands to both owners

credentials

Apply before retry

The coordinator waits for the compositor credential receipt. Only a changed result triggers the manager to retry that instance if it is pending.

package registry

Wake pending starts

A registry refresh is reported directly to the manager, which rechecks pending instances against the packages it uses to launch them.

delete or replace

Stop both sides

The coordinator deactivates or unregisters compositor state and separately asks the manager to stop the process.

Global transitions

Upgrade and shutdown close the start gate

1coordinatorPause or shut down the manager so no new child can cross the start boundary.
2coordinatorTell the compositor to deactivate retained widget instances and wait for the relevant work to finish.
3coordinatorOn resume, prepare compositor registrations and return the manager to running only for configuration that is still valid.

Review invariants

What must remain true

No PID routingWidget identity at the Wayland boundary is the canonical instance key.
No manager–compositor channelNeither component sends lifecycle results or events to the other.
Receipts gate initial spawnRegister and activate must succeed before the process is useful.
Crash recovery is localThe manager can respawn without coordinator or compositor round trips.
Changed credentials target retriesOnly an applied change wakes the matching pending instance.
Modes prevent racesPause and shutdown invalidate starts before broader transitions proceed.
